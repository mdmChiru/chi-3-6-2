# Vibe Venture

Лендинг-сайт (MVP) для [Vibe Venture](https://example.com) — небольшой
венчурной фирмы, которая помогает ИИ-стартапам на ранней стадии.

## О проекте

Vibe Venture ищет команды с понятной проблемой, прототипом или MVP и может
предоставить:

- микрогрант;
- продуктовую обратную связь;
- помощь с упаковкой питча;
- первые пилотные интро.

Пользователи сайта — основатели ИИ-стартапов. Они должны понять предложение
фирмы, открыть подробное описание компании и оставить заявку на первичный
отбор.

В проекте реализовано:

- лендинг с пятью секциями: «Главная», «О нас», «Плюсы», «Вопросы», «Форма»;
- второй экран «О нас» (`/about`) с переходом из секции «О нас» и кнопкой
  возврата на главную;
- форма заявки с клиентской валидацией и серверной валидацией через Zod;
- сохранение заявок в локальную базу SQLite;
- CSV-выгрузка заявок локальным Node.js-скриптом (`npm run export:csv`).

## Стек технологий

- [Next.js](https://nextjs.org/) (App Router) — фреймворк
- [React](https://react.dev/) — UI
- [TypeScript](https://www.typescriptlang.org/) — типизация
- [Tailwind CSS](https://tailwindcss.com/) — стили
- [Zod](https://zod.dev/) — серверная валидация формы
- [better-sqlite3](https://github.com/WiseLibs/better-sqlite3) — SQLite-база заявок
- Node.js — среда выполнения (dev-сервер и CSV-скрипт)

## Требования

- **Node.js 20.9.0 или новее** (LTS-версия рекомендована Next.js).
- npm (устанавливается вместе с Node.js).


## База данных (SQLite)

Заявки на первичный отбор сохраняются в локальную базу SQLite **после
успешной валидации Zod** на сервере (роут `POST /api/apply`).

Библиотека — `better-sqlite3`: быстрая нативная реализация SQLite для
Node.js, синхронный API без лишней обвязки, минимум кода для интеграции
и защита от SQL-инъекций через prepared statements.

- Файл БД: `data/applications.db` — путь задан в
  [`scripts/db-path.mjs`](scripts/db-path.mjs) и используется и приложением,
  и CSV-скриптом; файл создаётся автоматически, находится в `.gitignore`
  и не коммитится.
- Конфигурация подключения и миграция: [`src/lib/database.ts`](src/lib/database.ts).
- Таблица создаётся при старте сервера (`CREATE TABLE IF NOT EXISTS`).

### Структура таблицы `applications`

Имена полей формы (Zod) отличаются от имён колонок БД — это разные слои.
Соответствие приведено в таблице.

| Поле БД               | Тип      | Поле формы (Zod) | Описание                            |
| --------------------- | -------- | ---------------- | ----------------------------------- |
| `id`                  | INTEGER  | —                | Автоинкремент, первичный ключ       |
| `name`                | TEXT     | `founderName`    | Имя основателя                      |
| `contact`             | TEXT     | `contact`        | Контактные данные                   |
| `project_name`        | TEXT     | `projectName`    | Название проекта                    |
| `project_stage`       | TEXT     | `projectStage`   | Стадия: `idea` / `prototype` / `mvp`|
| `problem_description` | TEXT     | `problem`        | Описание решаемой проблемы          |
| `demo_link`           | TEXT     | `demoUrl`        | Ссылка на демо (пустая строка → NULL)|
| `created_at`          | DATETIME | —                | Время создания записи (UTC)         |

### Как проверить сохранение заявки

1. Запустите сервер (`npm run dev`) и отправьте форму на
   http://localhost:3000/#form.
2. Посмотрите содержимое базы:

   ```bash
   npm run db:show
   ```

3. SQL-запрос для проверки вручную (в утилите sqlite3 или через Node.js):

   ```sql
   SELECT * FROM applications ORDER BY id;
   ```

4. Повторная отправка формы создаёт новую запись со следующим `id` —
   данные не дублируются и не перезаписываются.

## CSV-выгрузка заявок

Локальный Node.js-скрипт читает заявки из SQLite и записывает их в CSV-файл.
Запускается вручную из терминала, без веб-интерфейса.

```bash
npm run export:csv
```

- Файл выгрузки: `data/applications-export.csv` (путь задан в
  [`scripts/db-path.mjs`](scripts/db-path.mjs); файл перезаписывается при
  каждом запуске; каталог `data/` и правило `*.csv` в `.gitignore` — файл
  не коммитится; исключение — каталог `examples/` с примером выгрузки,
  см. раздел «Пример выгрузки» ниже).
- Скрипт: [`scripts/export-applications.mjs`](scripts/export-applications.mjs).
- БД открывается в read-only режиме — не мешает работающему dev-серверу.
- Формат: UTF-8 с BOM (корректно открывается в Excel на Windows и macOS),
  перевод строки CRLF, значения с запятыми/кавычками/переносами корректно
  экранируются, `NULL` выводится как пустая строка.
- Заголовки: `id,name,contact,project_name,project_stage,problem_description,demo_link,created_at`,
  строки отсортированы по `id ASC`.
- Если заявок нет — создаётся файл только с заголовками.
- Если файл БД ещё не создан (сервер ни разу не запускался) — скрипт не
  завершается ошибкой: создаётся файл только с заголовками и выводится
  сообщение, что заявок пока нет.

### Как проверить выгрузку

1. Запустите сервер (`npm run dev`) и отправьте заявку через форму на
   http://localhost:3000/#form.
2. Выполните выгрузку:

   ```bash
   npm run export:csv
   ```

3. Откройте файл `data/applications-export.csv`:

   - **macOS:** `open data/applications-export.csv` (откроется в Numbers)
   - **Windows:** `start data\applications-export.csv` (откроется в Excel)

4. Убедитесь, что строка с вашей заявкой на месте, все поля заполнены,
   а русский текст отображается без «кракозябр» (BOM гарантирует корректную
   кодировку).

### Пример выгрузки

Пример результата CSV-выгрузки лежит в репозитории:
[`examples/applications-export.example.csv`](examples/applications-export.example.csv).

Как он создан:

1. Через форму на http://localhost:3000/#form отправлены 2 тестовые заявки
   (прошли клиентскую и серверную валидацию и сохранились в SQLite).
2. Выполнена команда `npm run export:csv`.
3. Файл `data/applications-export.csv` скопирован в `examples/` с суффиксом
   `.example`.

В отличие от `data/` и прочих `*.csv`, каталог `examples/` не игнорируется
(в `.gitignore` добавлено исключение `!examples/*.csv`), поэтому пример
можно открыть ещё до запуска проекта:

- **macOS:** `open examples/applications-export.example.csv`
- **Windows:** `start examples\applications-export.example.csv`

В примере 12 строк: 10 заявок из локальной базы предыдущих проверок и
2 новые тестовые заявки. Файл демонстрирует и экранирование по RFC 4180:
значения с запятыми, кавычками или переносами строк обёрнуты в двойные
кавычки (например, заявка «Тест, Запятая» с кавычками в названии проекта).

## Проверка end-to-end

Полный сценарий для ревьюера (одинаков на macOS и Windows, различия только
в командах открытия файлов).

1. **Установка зависимостей**

   ```bash
   npm install
   ```

2. **Запуск сервера**

   ```bash
   npm run dev
   ```

   Откройте [http://localhost:3000](http://localhost:3000).

3. **Проверка лендинга.** На главной странице должны быть секции:
   «Главная», «О нас», «Плюсы», «Вопросы», «Форма» (навигация — в шапке).

4. **Второй экран.** В секции «О нас» нажмите «Подробнее о компании» —
   откроется `/about` с подробным описанием. Кнопка «Вернуться на главную»
   возвращает на лендинг.

5. **Клиентская валидация.** В секции «Форма» нажмите «Отправить заявку»,
   не заполняя поля. Должны появиться ошибки у полей, а не сообщение об
   успехе.

6. **Отправка заявки.** Заполните форму корректно (имя, контакт — email,
   телефон или `@username`, название проекта, стадия, описание проблемы
   от 20 символов; ссылка на демо — необязательна) и отправьте. Сообщение
   об успехе появляется только после ответа сервера.

7. **Проверка базы.** Заявка должна появиться в SQLite:

   ```bash
   npm run db:show
   ```

   (или SQL-запрос `SELECT * FROM applications ORDER BY id;`).

8. **CSV-выгрузка.** Выполните:

   ```bash
   npm run export:csv
   ```

   Откройте `data/applications-export.csv`:
   - **macOS:** `open data/applications-export.csv`
   - **Windows:** `start data\applications-export.csv`

   Убедитесь, что строка с заявкой на месте, все поля заполнены, а русский
   текст читается без «кракозябр».
